# BUG-003 - `RevokeTokenAction` calls non-existent method `refreshTokens()` in Passport 13

**Severity**: P1 - Logout fails to revoke refresh tokens (exception swallowed)
**Status**: Fixed
**Found during**: Runtime verification session 2026-07-21

## Symptom

During logout, `RevokeTokenAction::execute()` threw:

```
BadMethodCallException: Call to undefined method Laravel\Passport\Token::refreshTokens()
```

As a result, access tokens were revoked but refresh tokens **were not revoked** (exception occurred in mid-loop, terminating iteration).

## Root Cause

`RevokeTokenAction` called `$token->refreshTokens()->update(...)` (plural). In Passport 13.x, this relationship is `refreshToken` (singular, `HasOne`), not `refreshTokens` (plural).

## Fix Applied

Updated `app/Actions/Auth/RevokeTokenAction.php`:

```php
// Before
$token->refreshTokens()->update(['revoked' => true]);

// After
$token->refreshToken?->update(['revoked' => true]);
```

Used the nullsafe operator because not all access tokens possess a refresh token (e.g., personal access tokens).

**File**: `app/Actions/Auth/RevokeTokenAction.php` — fixed in this session.
